# Progress-based local recovery

The owner approved this shared policy on 2 November 2026. It replaces numerical
local dispatch ceilings with a host-verified reason for each coding run. Original
task and issue identities, retained candidates, every earlier charge, frozen
paths and full final acceptance remain. The old two-launch extensions are spent
historical grants; they are never reset or renewed.

`midnight repair-status [PROJECT] --json` and the read-only dashboard show each
enrolled task's exact source/profile/stage, latest actual failure, checkpoint,
admission proof, earlier counts and next action. The daily scrum receives these
same host observations. Observation does not invoke a model or create a ledger.

Recovery diagnosis and its independent reviewer receive the same bounded
persistent Principal Architect context as ordinary planning/review. Only
committed decisions for the project or all projects change diagnosis identity;
routine chat cannot manufacture another diagnosis. Advice preserves every host
gate and is never itself a launch proof.

Independent narrowing review assesses the proposed repair plan. Its structured
admission fields must all support one unmet, permitted, non-repeated work unit
and preservation of full final acceptance. The host rejects contradictory or
incomplete responses and pins both the raw decision and its derived admission
receipt. Remaining defects outside that small repair stay required by later
work and full completed-code verification. Plan admission never accepts code.

## Admission and diagnosis

`progress_recovery.py` uses the existing private HistoryStore database. Immutable
scopes bind project, issue episode, original task fingerprint, stage, source and
protected profile. A genuinely new task gets one initial admission. Migrating a
failed task records its old dispatches and receives no fresh initial allowance.

Actual receipts distinguish semantic assertions, independent review findings,
unfinished handoffs, explicitly observed response truncation, runtime/control
interruptions and saved verification/delivery. An exit code of zero without a
verified submission is unfinished work. Missing evidence stays unknown.

After failure, the local planner sees bounded actual source, check output,
retained-candidate references, the latest failed run and original obligations.
Writable repair files take precedence over frozen parent files in the bounded
source excerpt. A saved intermediate candidate receives its first fixed host
verification and separate review before more coding is requested, even when the
worker never submitted. This preserves the actual unfinished worker receipt and
its charge; it creates no new coding launch and never promotes a partial patch.
A separate tool-free local reviewer may approve one genuinely smaller edit to
an original obligation. The host pins the saved proposal/review, evidence bytes,
live candidate pointer, source components and qualified model. A numbered
obligation is traceability, not a limit on distinct repairs. The host derives a
Python work-unit identity from the writable path and named syntax, excluding
comments, formatting, docstrings and definition names. Parent/file aliases of a
quoted method resolve to that same method. Different quotes, prose or obligation
indices cannot renew it. Without a language parser the conservative identity is
the writable file, with at most one narrowing proof per guidance generation.
Earlier broad unanchored proofs remain spent; they cannot prohibit a genuinely
different anchored repair. Prior proofs reach the planner and separate reviewer.
Any changed syntax still needs current failure evidence and independent review;
a changed hash alone grants nothing. The worker sees that smaller edit; the host
keeps every original semantic and final check.

One proof admits one launch transactionally. It is consumed in the actual
launch callback after resource and control checks, in the same transaction as
manager/microstep charges. Competing controllers cannot consume it twice. A
crash or uncertain launch remains charged. Changed evidence/model/source or
candidate pointers invalidate unconsumed proof. Repeated failure with no new
intervention returns to diagnosis and one stable Principal Architect question.
Other ready admitted work takes precedence over diagnosing a held task.

Existing immutable microstep plans still checkpoint only after focused host
checks and separate review. Intermediate patches remain private. Complete saved
results resume through the existing verification/delivery path without another
coding launch; the final stage retains the full original contract. No chat,
model rating, newly written test or intermediate checkpoint establishes product
acceptance.

## Codex harness responsibility

The local worker never repairs Midnight's harness. An evidence-backed harness
request enters the existing independent guardian/charged Codex maintenance path.
After explicit reviewed version-two adoption, [harness recovery](RECOVERY.md)
also uses one-use evidence admission and separate saved-work continuation.
The old four-attempt API remains available for unadopted installations and its
charges remain history. A new implementation proof is committed with its launch
intent after resource admission. The isolated clone, small source allowlist,
assertion-failing regression on the old source, unchanged full checks, separate
strongest-qualified Codex review, private checked PR and idle installation stay
in force. Original incident lineage crosses task wording and source generations.
Product rescue/audit spending limits remain unchanged.

Worker-contract repairs additionally run the immutable `worker_probe.py` through
the actual Ralphy → local_worker → structured_worker entry, with the selected
model, realistic existing-file/brief sizes, two disposable editing exercises,
fixed semantic oracles, exact scope and verified submission. The host owns the
single local lane and normal GPU lock. Model-authored solution code runs only in
the worker's existing test sandbox. macOS refuses nested sandbox-exec, so a fixed
native host broker runs the predetermined syntax checks in separate no-fork
sandboxes while the candidate typed client stays confined with process creation
denied. Ralphy's entry remains byte-identical to the trusted installed wrapper;
it invokes the fixed confinement proxy. Requests contain only case
and check identifiers, never commands or code. The final fixed semantic oracles
run after the candidate process has drained. There are no provider credentials
or product workspaces. The qualification oracle, broker and verifier are outside
the automatic maintenance writable allowlist.

After exact adoption, the fresh installed module revalidates review, regression,
patch, qualification, tree and confirmed merge. A certificate binds the original
failure's component hashes to changed qualified components. It becomes eligible
only after the installed generation passes health observation. Product actions
cannot register certificates; generic qualification alone is insufficient.

Legacy coordinator proofs are historical records. `Recovery.coordinator_proof_inventory()`
reads every such proof in one project's ledger without schema changes. After reviewed
adoption, backend recovery and dispatch preparation call
`Recovery.reconcile_coordinator_proofs()`: every unconsumed direct coordinator proof
gets a durable `legacy_coordinator_requires_review` hold and an atomic history event.
Consumed launches, including uncertain launches, and all original proof/result rows
remain byte-identical. Repeating reconciliation adds nothing. The admission kernel
already refuses direct coordinator proofs even before the hold is materialized.

Harness repair certificates retain their immutable registration hash, recorded
failure sources, exact model and worker qualification. New admission requires the
qualified worker sources and the current installed commit and tree to match a
verified installation-health record. Missing legacy fields remain held. Publication
may retain a pending certificate before health verification; this is not permission
to launch. Recheck these bindings at reservation.

Rehearse migration on a coherent SQLite backup before live adoption: record all
proof, scope, launch, result and diagnosis rows and original history events, reconcile
twice, and compare those originals byte for byte. Only the expected unconsumed-proof
holds and new history events may appear. Status reads never run this migration.
Rollback preserves the ledger and its holds. A source predating these admission
rules cannot interpret the new holds, so keep coding fenced if restoring that source;
restore admission only through the reviewed generation/health process.

Coordinator decisions journal their original input, source/model binding and call
intent before provider execution. Complete exact subprocess/provider receipts can
finish local validation after a crash; missing completion evidence remains charged
and held, without another provider request. An unlaunched prepared decision still
needs current daily capacity. Legacy decision errors and unjournaled run directories
are retained as uncertainty, never silently replayed.
Daily quota uses the persisted call-intent timestamp, separately from preparation;
older records keep their original charge date. Bounded round-robin reconciliation
lets unchanged holds yield capacity to other eligible work. Provider completion
files reconcile with the invocation database without replacing their timestamps;
conflicts remain held. A recorded profile mismatch remains a failed attempt when
recovering a completed selected-provider fallback.

Effects recheck current membership, source, model, pauses and mode after waits and
inside the project effect lock. Completed advice and retirement can be read back
after an interrupted effect receipt. A temporary pause may resume the same saved
answer after current checks pass; it does not repeat inference. Owner overrule and
restoration retain decision-specific withdrawal records before reversing effects.
These records also block advice-bound admission if interruption precedes ledger
revocation. An old overrule cannot remove a newer retirement.
Malformed, unreadable or unsafe withdrawal history holds both effects and further
withdrawal writes; it is never interpreted as empty or overwritten.

Event emission reconciles exact existing local events. Notification intent precedes
the OS helper: an interrupted notification remains uncertain and is not resent.
Neither helper success nor a coordinator decision means visible notification
delivery, product acceptance or permission to retry unchanged harness failures.

## Preserved boundaries

Routine planning, diagnosis, implementation and independent review stay local.
New committed Codex guidance may admit its same-issue guided transition; old
guidance present during migration cannot be recycled. Exceptional cloud product
rescue still requires two verified initial failures, saved Codex guidance, two
guided failures and the existing manager decision and rolling quotas. No paid
call allowance increases. Daily paid quotas apply to paid phases and do not
block eligible local work; local launch counts remain visible history.

Schedule/24-hour override, live global/project pauses, bounded deadlines,
resource capacities, model qualification, account identity, project membership,
protected profiles, quality audits and publication authority remain. A clear
repair-only scope is legitimately idle. Evidence admission does not invent a
feature, reopen accepted work, broaden publication or guarantee a hard problem
can be solved. When no intervention qualifies, the state names Codex and the
specific evidence/decision needed instead of asking for another numerical top-up.

This implementation uses the existing standard-library ledger, action store,
worker checks and Ralphy adapter. No additional orchestration framework or
external messaging dependency is needed; vendored upstream notices remain.

## Small current evidence for sustained local work

Recovery diagnosis and its separate admission reviewer receive a compact current
evidence capsule. It retains the complete original description and acceptance,
current microstep contract, writable paths, actual source excerpts and their
truncation markers, check results, committed Codex guidance and audit findings.
It omits duplicated manager-history prose, successful-check log bodies and old
model repair instructions. Used source-unit identities remain visible, while
the full immutable host evidence and every spent reservation stay authoritative.
A capsule too large for its bound needs a smaller host scope before inference;
it never silently drops an original requirement.

New diagnosis and code-review chat frames retain complete current scoped
Principal decisions, including holds. Ordinary conversation remains in a saved
snapshot instead of competing with the current source and checks. Existing saved
decisions keep their exact receipt and do not acquire a fabricated new review.
Codex can explicitly supersede obsolete same-scope guidance without deleting its
history or releasing a hold. This supports repeated small verified improvements
across registered projects; merely keeping a process or model busy is not work.

Python edits are parsed before atomic publication, using the same intrinsic
syntax requirement as the worker's existing handoff check. A rejected edit leaves
the current file, write set and last passing test receipt untouched. The worker
gets the exact parser location and may submit a corrected bounded replacement.
Already retained invalid drafts can still be repaired atomically. This executes
no candidate code and adds no shell command or broader file permission. Original
semantic checks and final review remain mandatory. Non-Python files retain their
existing language/profile checks.

When a worker is interrupted before its completion receipt, source provenance
can be recovered from its consumed host proof. Recovery verifies the proof hash,
exact scope/run, launch and proof model against the recorded worker model, and
the source-component hashes. It records a separate immutable provenance receipt;
it does not infer completion, replace the failed outcome or refund the launch.
Missing legacy evidence remains unknown. This lets a separately reviewed and
qualified harness repair address a genuinely matching interrupted worker.

Bounded edit inference uses the complete original host instructions, full current
file, selected action and the latest distinct tool errors. Earlier file reads and
conversation are retained in host receipts instead of duplicating the current
file in the edit prompt. A history hash records the omitted conversation. The
90,000-byte edit bound is unchanged. If the complete contract plus current file
still exceeds it, the host refuses edit inference without truncating either,
changing a file or treating the refusal as completed work. All existing read,
write, parser, model, submission and semantic acceptance checks remain.
